# bitig Audit — v0.3.1

**Date:** 2026-09-26
**Audited revision:** `941231c` (release 0.3.1)
**Scope:** (A) regression check of all 67 items from the v0.2.0 audit (`design/audit-2026-06-03.md`); (B) a fresh audit across four areas: forensic integrity & security, method correctness, code/tests/CI, and docs vs behaviour.
**Method:** Two regression checkers and four independent auditors, each reading the current code and re-running repro scripts. A separate agent then tried to refute every finding from the fresh audit (91 raw findings, 0 refuted, 3 left "plausible" rather than confirmed). The lead reproduced the headline P0 by hand and checked the CI status on GitHub. Duplicates across areas were merged below. The result: **2 P0, 16 P1, ~40 P2, ~10 P3**.
**Verdict:** **Not court-ready, and the Forensic Lab Case workflow does not work end-to-end.** The 0.3.x remediation fixed a lot of real defects: the self-referential seal hash, the path-traversal bugs, the classification of the verbal rung from rounded display strings, ZetaEder, EderDelta and the `loao` CLI default. But the court-facing path still has an HMAC bypass, a seal that doesn't cover what gets analysed or shown, and no shipped recipe that can actually run.

---

## 1. Executive summary

- **The Case workflow cannot produce a result (new P0).** `Case.resolved_study_dict()` points `corpus.path` at `evidence/`, while `add_evidence()` stores files in `evidence/<role>/`. `load_corpus` globs non-recursively, so every Case run fails with `no files matching '*.txt'`. Reproduced: `perform_run()` on a fresh `imposters_lr` case returns `status='failed'`. Get past that and every one of the 5 recipes still crashes on parameter-name mismatches (`top_n`, `delta/iterations/subset_fraction`, `algorithm`, `craig`, `argamon`). Nothing maps questioned/known roles to `target_ids`/`candidate`/`group_by`. CI stays green because every `perform_run` test monkeypatches `run_study` and `test_recipes` only validates the schema.
- **The HMAC seal can be stripped (new P0; residual of old P1.1).** `verify_seal` reads the plugin id from the attacker-editable `signed.json` and treats `"null"` or a missing `signature` as a pass. It never compares against `case.json` and doesn't require a signature when the verifier supplies a key. Forge `signed.html`, recompute the plain hashes, delete `signature`, and `bitig case verify --key K` prints "seal verified — intact" (exit 0).
- **The seal doesn't cover what matters.** Unregistered files in `evidence/`, a hand-edited `study.yaml`, or a moved case all change what gets analysed while custody still reports clean. A case can be sealed with results from a run that predates the current evidence. Figures and `result.json` are outside the seal. `fork_case` re-hashes doctored evidence into a clean chain of custody. A failed sign leaves a stale `signed.html` behind, which then gets sealed.
- **Court-facing wording still overstates the evidence.** The forensic report prints "The likelihood ratio above…" when no LR exists; the "not an LR" disclaimer is shown only in the GUI. The headline "GI score" is the max across all questioned documents. GI defaults (1 impostor per iteration, threshold 0.5 = chance) "verify" 60% of texts by unrelated authors in a synthetic repro. Isotonic calibration gives log10 LR = ±12 ("extremely strong support") from 6 trials. The report template and docs state verbal-scale bands that contradict `LR_LADDER`.
- **Silent wrong results in the general stylometry path.** `run_study` never passes `preprocess.language`, so Turkish, German, Spanish and French studies use English function words and English readability formulas, including the shipped Turkish example. `method: cosine`, as the docs show it, silently runs Burrows. The seed isn't threaded into k-means, t-SNE, MDS, UMAP or consensus, so the documented byte-identical reproducibility is false. `Corpus.hash` doesn't bind texts to their ids or labels.
- **CI blind spot persists.** The `extras (gui + report + pdf)` job failed at the mypy step in each of the last three scheduled runs on `main` (latest: run 32698287327, 2026-08-24), so its pytest step is skipped. The GUI, report and PDF tests the old audit asked for have never run in CI. Old P1.19 is **not fixed**. Slow tests, including consensus, Bayesian and embeddings, run in no CI job.

## 3. New findings — P0 / P1 (full detail)

IDs are prefixed `N` to distinguish them from the v0.2.0 IDs. Where a new finding is the residual of an old one, the old ID is given.

### P0

#### N-P0.1 — No Forensic Lab recipe can run inside a Case; tests mock the runner so CI never sees it
**Files:** `src/bitig/cases.py:592-603` (`corpus_path=evidence_dir`); `src/bitig/io/ingest.py:63` (non-recursive glob); `src/bitig/recipes.py:73-83,94-101,118,146,170-183,201-212,231-240`; `src/bitig/runner.py:108-120,197,238-262`; `tests/test_case_run.py` (all tests patch `run_study`); `tests/test_recipes.py:31` (schema-only).
**What's wrong:** There are three layers of breakage.
1. The corpus path is `evidence/`, but files live in `evidence/questioned|known/`. Every run fails with `no files matching '*.txt'`.
2. Recipe params don't match constructors. `MFWExtractor`/`WordNgramExtractor` take `n`, not `top_n`. `GeneralImposters` takes `base_delta/n_iter/feature_frac`, not `delta/iterations/subset_fraction`. reduce/cluster read `variant`, not `algorithm`. `zeta` has no `craig`. The delta registry key is `argamon_linear`, not `argamon`. Bayesian has no `group_by`.
3. Evidence role and author never reach the runner: there's no metadata TSV, and no `target_ids`, `candidate` or `group_by` derived from the questioned/known entries. The GUI "+ Add file" never sets `author`.

**Repro:** A real `Case.create(recipe='imposters_lr')` with 1 questioned and 2 known files, then `perform_run(case)`, gives `RunOutcome(status='failed', message="ValueError: …/evidence: no files matching '*.txt'")`. Reproduced independently by three auditors and by the lead. On a flat corpus with metadata, 4 recipes raise `TypeError … 'top_n'` and bayesian fails with `'<' not supported between NoneType`.
**Severity note:** The failure is loud, not silently wrong, so one verifier argued for P1. It is P0 here because the product's court-facing workflow, and the default recipe of `bitig case new`, cannot produce any result.
**Fix:** Build the run corpus from the registered `EvidenceEntry` list: exact paths, re-hashed at load, with role and author as metadata. Derive `target_ids`, `candidate` and `group_by` from the roles. Align the recipe keys with the constructor signatures, or validate method and feature params against those signatures when `StudyConfig` loads. Add an un-mocked end-to-end test per recipe on `tests/fixtures/mini_corpus`.

#### N-P0.2 — `verify_seal` accepts a stripped or downgraded HMAC signature (residual of P1.1)
**Files:** `src/bitig/cases.py:943-952`; `src/bitig/cli/case_cmd.py:337-370`; `src/bitig/signatures.py:119-135,169-189`.
**What's wrong:** `plugin_id` is read from `signed.json`. `if plugin_id == "null" or sig is None` passes. There is no cross-check against `record.signature_plugin_id` (still `"hmac"` in `case.json`), and a supplied `signature_key` does not make a signature mandatory.
**Repro:** Sign with `HmacSignaturePlugin('secret')`. Overwrite `report/signed.html`, recompute `report_html_hash`, and `del payload['signature']`. `verify_seal(signature_key='secret').ok == True`. Reproduced by three agents.
**Why it matters:** HMAC is the only protection against someone who can write to the case directory, and it can be removed in three edits. The CLI and the GUI "Verify seal" both certify the forged report.
**Fix:** Fail when `case.json` and `signed.json` plugin ids differ. Fail when either says non-null and the signature is missing or malformed. Require a valid signature whenever a key is supplied. Make the expected plugin a verifier input, not a payload field. Add strip and downgrade regression tests.

### P1 — Forensic integrity (chain of custody and seal)

#### N-P1.1 — What gets analysed is not bound to the chain of custody
**Files:** `src/bitig/case_run.py:71-81`; `src/bitig/cases.py:502-511,598-603`; `src/bitig/recipes.py:302-311`; `src/bitig/runner.py:98-100`.
**What's wrong:** `perform_run` checks only `verify_custody()`, which covers registered entries, then runs whatever `study.yaml` says.
- (a) An unregistered `*.txt` in `evidence/` is loaded while custody reports clean.
- (b) A hand edit of `study.yaml`, e.g. `corpus.path` pointing elsewhere, isn't detected. The next `save()` re-hashes the edited file into `study_hash`, which blesses the edit.
- (c) `corpus.path` is absolute, so a copied case analyses the original machine's evidence.

Nothing compares the run's provenance `corpus_hash` with the registered evidence. The effect is latent until N-P0.1 is fixed.
**Fix:** Load only registered entries (see N-P0.1). Refuse to run on a `study_hash` mismatch, and don't let `save()` silently adopt edits made on disk. Make the corpus path case-relative. After the run, assert `corpus_hash` equals the hash of the registered content.

#### N-P1.2 — A case can be sealed with results from a run that predates the current evidence or study
**Files:** `src/bitig/cases.py:697-785,793-844`; `src/bitig/report/case_report.py:104-110`; `src/bitig/report/scalars.py:38-65`.
**What's wrong:** `mark_signed` renders from `latest_run`, whatever state that run was computed on. Adding evidence or changing params after the run doesn't invalidate it. **Repro:** run R1 on 2 files, add a 3rd, and `mark_signed()` succeeds. The sealed custody table lists 3 files while the results come from 2.
**Fix:** Record the `case_state_hash` in each run dir. Refuse to sign when it differs from the current state. Clear `latest_run` on any evidence or study mutation.

#### N-P1.3 — A failed sign leaves `signed.html` behind; the next successful seal freezes a stale report (residual of P1.5)
**Files:** `src/bitig/cases.py:736-783`; `src/bitig/report/case_report.py:78-81`.
**What's wrong:** `draft.html` is copied to `signed.html` before `plugin.sign()`. The rollback restores record fields only. `build_case_report` freezes on the existence of `signed.html`, so an unsigned case shows a SIGNED banner, and the next `mark_signed` seals the stale snapshot. In the repro, the sealed report omitted evidence added in between and named the earlier signer. The rollback catches only `Exception`: an interrupt after the first `save()` leaves `signed=true` with no `signed.json`.
**Fix:** Write to temp names and `os.replace` only after everything succeeds. Unlink on rollback. Freeze on `record.signed` plus a valid seal, not on file existence. Persist `signed=True` last.

#### N-P1.4 — `fork_case` launders tampered evidence into a fresh chain of custody
**Files:** `src/bitig/cases.py:994-1044`; `src/bitig/case_run.py:73-77`; `src/bitig/gui/pages/case/report.py:89-92`.
**What's wrong:** Fork re-hashes the current bytes through `add_evidence` and never calls `verify_custody()` on the source. Doctored evidence gets clean hashes in the fork. The UI tells analysts to "Re-acknowledge on the Evidence step", a feature that doesn't exist, which leaves fork as the only way forward.
**Fix:** Refuse to fork when source custody fails, unless an explicit acknowledgement is recorded in the fork. Store the parent id and original hashes. Implement the re-acknowledge flow or remove the message.

#### N-P1.5 — Report figures and `result.json` are outside the seal (residual of P0.1, P1.7 and P1.8)
**Files:** `src/bitig/report/case_report.py:91-95,221-240`; `src/bitig/cases.py:793-869`.
**What's wrong:** `signed.html` references figures by path, and `report_html_hash` covers only the HTML text. The canonical state excludes `runs/`. Replacing a plot or `result.json` after signing still gives `verify_seal().ok == True`, and Export PDF embeds the replaced figure. Separately, the `runs/...` src paths are relative to the case root, so the sealed HTML opened in a browser from `report/` shows broken images. The P1.8 fix covered only the PDF `base_url`, and its regression test passes on the old code too.
**Fix:** Inline figures as `data:` URIs at sign time, or hash every referenced artefact into `signed.json` and check those hashes in `verify_seal` and before export. Emit `../runs/...` paths.

#### N-P1.6 — Export PDF never checks the seal, and re-renders a SIGNED-banner draft when `signed.html` is absent
**Files:** `src/bitig/report/case_report.py:78-96`; `src/bitig/gui/pages/case/report.py:76-78,106-117`.
**What's wrong:** Take a signed case without `signed.html`: a legacy 0.2.x case, or one where the file was deleted. Export re-renders from current run data under "● SIGNED". **Repro:** sign, delete `signed.html`, edit the `result.json` score to 0.11, and the export shows SIGNED with 0.11.
**Fix:** When `record.signed`, require `signed.html` and `verify_seal().ok` before any export. Never render a draft for a signed case.

#### N-P1.7 — Evidence placed as instructed is never registered; CLI and core signing have no preconditions (residual of P1.9)
**Files:** `src/bitig/cli/case_cmd.py:96-98,305-316`; `src/bitig/cases.py:515-590,697-790`; `src/bitig/gui/pages/case/report.py:85-95`.
**What's wrong:** `bitig case new` says "drop questioned/known files into `<case>/evidence/`", but no CLI command registers evidence. Dropped files are invisible: status shows `questioned=0, known=0, custody: OK`. A case can be signed with zero evidence and zero runs, and after the dropped file is modified `bitig case verify` still prints "intact" (exit 0). The custody-before-sign guard exists only in the GUI handler, so `bitig case sign` and `Case.mark_signed` seal tampered evidence.
**Fix:** Add `bitig case add-evidence`. Flag unregistered files in status, sign and verify. Move the custody, has-evidence and has-successful-run checks into `mark_signed`.

### P1 — Forensic reporting & calibration

#### N-P1.8 — The sealed report describes a GI score as a likelihood ratio (residual of P1.10)
**Files:** `src/bitig/report/case_report.py:133-139,274-281`; `src/bitig/report/templates/forensic.html.j2:71-109`; `src/bitig/gui/pages/case/report.py:192-212`.
**What's wrong:** No production path yields `lr`/`log_lr` (`CalibratedScorer` isn't wired in). Yet the method paragraph always reads "The likelihood ratio above expresses how much more probable the observed evidence is under H_p than under H_d", under an Hp/Hd block. The "Uncalibrated … not a likelihood ratio" disclaimer and the chance level exist only in the GUI preview, never in `signed.html` or the PDF.
**Fix:** Branch the paragraph on whether an LR exists. Put the disclaimer and chance level in the template. Drop the Hp/Hd LR framing without a calibrated LR.

#### N-P1.9 — Headline "GI score" is the maximum over all questioned documents
**Files:** `src/bitig/report/scalars.py:39-54,72-83`; `src/bitig/methods/imposters.py:236-243`.
**What's wrong:** `values['scores']` is keyed by target document id. `gi_score` looks up the candidate's author label, which never matches, and falls back to `max()`. **Repro:** `{'QA9': 1.0, 'QB9': 0.0}` gives a headline of 1.0. `latest_result_path` also picks the alphabetically first method dir.
**Fix:** Report per-target scores with chance, or require exactly one questioned target. Never aggregate with max. Select the result by method kind.

#### N-P1.10 — `GeneralImposters` defaults put the decision boundary at chance
**Files:** `src/bitig/methods/imposters.py:11-16,71-76,102-103,203-221`; `src/bitig/runner.py:239-256`.
**What's wrong:** With `impostor_n=1`, the candidate is compared against a single impostor per iteration, so with no signal it wins about 50% of iterations. The default threshold is 0.5 and `verified = score >= threshold`. Koppel & Winter (2014) and Kestemont et al. (2016) compare against a set of impostors. **Repro:** 20 texts by authors outside the candidate set gave a false-verified rate of 0.60 at defaults and 0.10 with `impostor_n=7`. The docstring acknowledges that the threshold sits at chance but still emits the boolean. `forensic.verify.GeneralImpostors` uses different defaults (`ceil(sqrt(pool))`) and there is no parity test between the two.
**Fix:** Default `impostor_n` to a real set size. Reject `threshold <= chance`, or drop the `verified` flag until scores are calibrated. Consolidate the two implementations.

#### N-P1.11 — Isotonic calibration yields log10 LR = ±12 ("extremely strong support") from tiny or separable sets
**Files:** `src/bitig/forensic/lr.py:39-66,124-157`; `src/bitig/forensic/verbal_scale.py:44-51`; `docs/site/forensic/calibration.md:13,57,59,74`.
**What's wrong:** `IsotonicRegression(out_of_bounds='clip')` outputs exactly 0 or 1 wherever the extreme bins are pure, and `log_lr_from_probs` clips at `eps=1e-12`, so the magnitude is set by `eps` rather than by the data. **Repros:** 6 trials give `[12.0, -12.0]`, i.e. "extremely strong support" for both prosecution and defence. With 200 trials per class, scores of [2.5, 3, 5, -3] give ±12 where the true values are [2.17, 2.61, 4.34, -2.61]. The minimum is 4 trials, and the ≥100/class advice appears only in a docstring. The docs also claim "AUC is unchanged" (false: isotonic creates ties; 0.931 → 0.921) and give inconsistent sample-size guidance (≥100 vs ≥500).
**Fix:** Add pseudo-counts (PAV with smoothing), cap |log10 LR| using an empirical bound tied to the calibration size (ELUB, Vergeer et al. 2016), enforce a minimum trial count, and warn when outputs hit the clip. Fix the docs.

#### N-P1.12 — The verbal-scale bands in the `build_forensic_report` template and the docs contradict `LR_LADDER` (residual of P2-dup-1 and judgment 1)
**Files:** `src/bitig/forensic/verbal_scale.py:32-39`; `src/bitig/report/templates/forensic_lr.html.j2:60-68`; `src/bitig/report/render.py:94-152`; `docs/site/forensic/reporting.md:3-25,99-114`; `docs/site/forensic/calibration.md:98-112` (plus the `.tr.md` pages).
**What's wrong:** `LR_LADDER` puts "very strong" at 10^4–10^6 and "extremely strong" at ≥10^6 (ENFSI 2015). The public template footnote and the EN and TR docs say "4–5 very strong, >5 extremely strong". The template never computes a statement from the LR; it only echoes caller strings. The docs promise a Tippett plot and PDF export for this function, and neither exists.
**Fix:** Render the rung and statement from `lr_verbal_statement()` and the table from `ladder_rows()`. Generate the docs tables from `LR_LADDER`. Add a parity test. Remove or implement the Tippett and PDF claims.

### P1 — General stylometry correctness & reproducibility

#### N-P1.13 — `run_study` ignores `preprocess.language`
**Files:** `src/bitig/runner.py:100-102`; `src/bitig/io/ingest.py:46`; `src/bitig/features/function_words.py:67`; `src/bitig/features/readability.py:71`; `examples/turkish_seyfettin/study.yaml`.
**What's wrong:** `load_corpus` is called without `language=`, so `corpus.language` is always `en`. Function-word, readability, embedding and distortion features fall back to English. The shipped Turkish example's `tr_fwords` columns are `['a','about','above',…]`, while provenance still records the `tr` pipeline. This contradicts the docs' multi-language claims.
**Fix:** Pass `language=cfg.preprocess.language`. Add an integration test asserting Turkish function-word columns and Ateşman.

#### N-P1.14 — The documented `method:` key doesn't select the Delta variant
**Files:** `docs/site/reference/config.md:23,78,131` (plus TR); `src/bitig/runner.py:197`; `src/bitig/scaffold/templates/study.yaml.j2:21`; `examples/*/study.yaml`; `docs/site/tutorials/federalist.md`.
**What's wrong:** The runner reads only `params['variant']`. `method: cosine` runs Burrows, and result.json records `method_name='delta_burrows'` with `params={'method':'cosine'}`.
**Fix:** Accept `method` as an alias, or reject unknown params with `extra='forbid'`. Update the docs, the scaffold and the examples.

#### N-P1.15 — The reproducibility contract is false: the seed is not threaded into stochastic methods
**Files:** `src/bitig/runner.py:147-154,275-306`; `src/bitig/methods/cluster.py:52`; `src/bitig/methods/consensus.py:26-28`; `docs/site/concepts/results.md:61-72`; `docs/site/reference/config.md:33`.
**What's wrong:** KMeans, t-SNE, MDS and UMAP get no `random_state`. `BootstrapConsensus` always uses seed 42, and `subsample` and `support_threshold` are dropped. SVC and RF estimators are unseeded. Provenance records `cfg.seed` anyway. **Repro:** four runs at `seed=7` gave four different k-means label vectors. The docs promise byte-identical `result.json`, which the provenance timestamp alone already rules out.
**Fix:** Thread `derive_seed(cfg.seed, method_id)` via `setdefault`. Forward all consensus params. Reword the byte-identity claim. Add a run-twice determinism test.

#### N-P1.16 — `Corpus.hash` doesn't bind texts to their ids or labels
**Files:** `src/bitig/corpus/corpus.py:87-92`; `docs/site/concepts/corpus.md`.
**What's wrong:** The hash is `sorted(text hashes)` plus `sorted((id, meta hash))`, two lists sorted independently. Swapping two documents' texts between Hamilton and Madison leaves `corpus_hash` unchanged. (The Case seal uses role:path:sha256, which does bind them.)
**Fix:** Hash sorted `(id, text_hash, metadata_hash)` tuples. Bump and document the hash version.

## 4. New findings — P2 (terse)

**Forensic / security**
- `latest_run` and `runs` from an untrusted `case.json` aren't validated. `latest_result_path` and `_list_figure_paths` read `result.json` and rglob figures outside the case, and WeasyPrint embeds them (`cases.py:456-471`, `report/scalars.py:45-54`, `case_report.py:221-240`).
- `bitig case fork` doesn't validate the source id: `fork ../outside/victim` loads and writes outside `--cases-dir` (residual of P1.3; `cli/case_cmd.py:269`, `cases.py:1013`). `case verify --key` exposes the secret on argv.
- With the default Null plugin, verify prints "seal verified — intact" (exit 0) although anyone with write access can recompute every hash. The GUI can only sign with Null, and GUI Verify passes no key, so intact HMAC cases show FAIL. The `signatures.py` docstring still claims the Null seal defends against tampering.
- `signed_by`, `bitig_version` and `signature_plugin_id` aren't covered by the HMAC (whose message is only `case_state_hash|report_html_hash|signed_at`), and aren't cross-checked against `case.json`. The signer can be changed after signing.
- Stale `Case` handles overwrite `case.json` wholesale. A long GUI run finishing after a sign un-signs the case (`signed=False`, seal broken), and evidence registered through another handle is silently dropped. `register_run` has no `_require_unsigned`. The temp file name is keyed only on pid, so threads collide (`cases.py:304-313,502-511,665-689`).
- The control corpus is listed in the chain-of-custody table but never used by any runner code.
- `list_cases` aborts on one malformed `case.json`, which takes down `bitig case list` and the GUI landing page.
- The DocBin cache is deserialised with no integrity check, and the cache dir is CWD-relative (old P2-sec-1, not fixed).
- Turkish extra: `torch<2.6` is affected by CVE-2025-32434 (`torch.load` RCE even with `weights_only=True`), and stanza 1.6 loads full pickles. It also breaks `transformers` weight loading together with `[embeddings]`. *(Plausible; the CVE applicability to the exact pinned versions was not tested.)*

**Methods / metrics**
- `f05u` and `c@1` deviate from PAN (Bevendorff et al.). `f05u` uses a [0.4, 0.6] non-answer band and counts only y=1 non-answers. `c@1` at margin 0 answers p=0.5. `compute_pan_report` claims PAN parity. Repro: 1.0 vs 0.625.
- `CalibratedScorer` assumes a balanced calibration set: the prior isn't stored or divided out. On uninformative 1:9 data, log10 LR = −0.9 (documented in a docstring, but not enforced).
- MFW "relative frequencies" are renormalised over the retained vocabulary, not document length, so values depend on `n`. With n=1 every z-score is 0 (`features/mfw.py:88-135`; copied in `imposters.py` and `rolling_delta.py`).
- Classification CV leaks: the MFW vocabulary and z-score stats are fit on the full corpus before `cross_val_predict`.
- The runner accepts `cv.kind=loao` with `groups_from == group_by` (degenerate, ~0 accuracy); only the CLI rejects it (residual of P1.16).
- The Bayesian runner branch reports resubstitution accuracy as `accuracy`, the same issue the delta branch already fixed.
- Bootstrap consensus subsamples documents and then counts reduced-tree clades as full-corpus clades. That is not Eder's (2017) feature-band bootstrap, and `>= 0.5` admits conflicting clades.
- `HierarchicalGroupComparison` defines `sigma_group` but hard-codes `sigma=1`. Priors are unscaled, and `group_by` is unused.
- GI with `base_delta='eder'` applies rank weights to randomly ordered columns (`imposters.py:196-202`).
- `FunctionWordExtractor(scale='zscore')` silently returns raw counts. 57 English and 13 French apostrophe entries can never match the tokenizer.
- The char/word n-gram extractors z-score raw counts (length-driven), have no `max_features`, and densify the full vocabulary.
- Unmasking accepts a 1-word tail chunk as a sample (a 1001-word text with chunk=500 gives [500, 500, 1]).
- German and French syllable counts via pyphen undercount ("Abend", "Oma", "ami", "école" all give 1): 51 vs 58 syllables on a 32-word sample.
- HD-D returns 0.0 for texts under 42 tokens, the same inversion that MTLD fixed.
- MTLD is still non-monotonic near maximum diversity: 100 unique tokens give 100.0, one repeat gives 2800.0 (residual of P1.13).
- The Bayesian attributor has no guard on `predict`, NaN input or `l2` scale (residual of P1.15).
- Bezirci-Yılmaz uses word fractions instead of per-sentence counts for H3–H6. *(Plausible; not checked against the paper's worked example.)*

**Code / tests / CI**
- `bitig run` exits 0 with "run complete" even when every method fails. `error.txt` holds only `str(exc)` with no traceback.
- The schema accepts settings the runner ignores (`preprocess.normalize`, `spacy.device`, `viz.*`, `cache.dir`, `report.*`, `cv.folds`). It also accepts `group_kfold` and four feature types that then fail at run time.
- Reusing a run dir (`timestamp: false`, which all examples use) mixes stale method outputs with new ones.
- Load-bearing logic is duplicated without parity tests: two GI implementations, and the MFW projection hand-copied into `imposters.py` and `rolling_delta.py` through private attributes.
- CI: `-m slow` runs nowhere. The embeddings skip guard is broken (8 failures when run locally). The multilang jobs download models that the tests never use.
- `publish.yml` doesn't depend on any test workflow (a tag on a red commit ships), has no top-level `permissions:`, uses the uv cache in the release build, and uses mutable action refs. `workflow_dispatch` skips the version check (old P2-ci-2).
- English readability triggers an NLTK `cmudict` download at run time, which breaks on air-gapped workstations. Versions of textstat, nltk, pyphen and cmudict aren't in provenance.
- Provenance records `spacy_model='en_core_web_trf'` even when no parse happened and the model isn't installed.

**Docs vs behaviour**
- The Forensic Lab Case workflow is absent from the README and the docs nav (old P2-ci-5, not fixed).
- README and quickstart PCA claims are false: #50 isn't in the figure, and Hamilton and Madison don't split left/right.
- Getting-started: the scaffold description is wrong, the Python snippet raises `AttributeError` (`fit_predict`), and `bitig info` doesn't summarise a corpus.
- The CLI reference has drifted: `--output-dir`, `cache info`, "all method commands accept `--seed`", and feature types that the CLI rejects. `case` and `gui` are undocumented.
- The config reference documents keys that are rejected (`corpus.strict`) or ignored (`cv.folds`).
- The Federalist tutorial claims a projection step that doesn't exist, ~35% PCA variance (measured 10–13%), 12 disputed papers instead of 11, and "effectively certain" posteriors from uncalibrated Naive Bayes. Joint papers are included in Bayesian training.
- The Turkish tutorial describes outputs and analyses (parquet tables, heatmap, `provenance.json`, a leave-one-out grid) that don't exist.
- The PAN-CLEF tutorial's expected output is impossible (20/20 trials where the code yields 19/13; ECE 0.04 vs 0.19). It also presents a mean log-LR over mixed trials as the case LR.
- `methods.md` and `features.md` have wrong signatures (`KMeansCluster(seed=)`, `HierarchicalGroupComparison`, `PosNgramExtractor`) and wrong LOAO guidance.
- The GUI Study page's k-means, HDBSCAN and Bayesian options always fail (the GUI always adds `linkage='ward'`/`n_clusters`, and uses z-scored MFW for Bayes), although the README advertises them.
- GI `aggregate='nearest'` is documented as "conservative" but biases toward H1: it more than doubles the same-author score under the null.
- The topic-invariance docs misstate the defaults: the default is all 7 categories, not affix+punct, and `dv_sa` is not POS-selective.

## 5. New findings — P3 (terse)

- Two incompatible Brier and ECE definitions share the same names (`metrics/calibration.py` vs `forensic/metrics.py`); the multiclass Brier is exactly 2× the binary one.
- The research-mode headline scalars never match actual method names (`classify_logreg`, `bayesian_authorship`), so those branches are dead.
- `lr_from_values`: `log_lr ≳ 308` raises `OverflowError` (which crashes the render and rolls back the sign), `log_lr ≤ -324` vanishes, and `inf` gives "extremely strong" (residual of P3-4).
- Yule's I is a hybrid formula (V²/(M2−N)) and returns 0 for all-hapax text.
- Distortion is attributed to Stamatatos (2013). DV-MA/DV-SA come from Stamatatos (2017), which also masks digits.
- `EderSimpleDelta` is Manhattan on z-scores (Burrows × n), not stylo's sqrt-frequency Simple Delta. *(Plausible; stylo source not checked.)*
- GUI and thread hygiene: the run button stays disabled after an exception, sign/export/verify block the event loop, pyplot is used from worker threads, the cache key omits the model version, cache `put()` is non-atomic, and dialogs leak (old P3-7).
- `_validate_case_id` uses `re.match` with `$`, so a trailing newline is accepted.
- Stale claims: the README says "Remaining — PyPI publish" (0.3.1 is on PyPI), test counts differ (700 / 417 / 676 actual), `CITATION.cff` claims "feature parity with Stylo", and CLI help leaks "spec §6" and "audit P1.1".
- Signer identity shown in the CLI and GUI is read from the unprotected `case.json`.

## 6. Cross-cutting themes

1. **Tests mock the seams where the bugs are.** `perform_run` tests patch `run_study`, recipe tests check only the schema, and the PDF test skips silently. Every P0 and most P1s sit exactly on an untested integration boundary. Several "regression tests" added in 0.3.0 would pass on the old code.
2. **The schema is looser than the runtime contract.** Pydantic accepts arbitrary params (`method`, `top_n`, `algorithm`, `folds`) that the runner ignores or crashes on. One `extra='forbid'`, or signature-checked validation, would have caught N-P0.1, N-P1.14 and the ignored-settings finding.
3. **The seal covers the record, not the evidence of the analysis.** Custody hashes registered files, but the run reads a directory, the report embeds unsealed files, and verification trusts fields in the file it is verifying.
4. **Court-facing text is hand-written in several places.** The LR wording, the verbal-scale footnote and the docs tables are each maintained separately from `LR_LADDER` and from what the pipeline produces (GI scores, not LRs).
5. **A red CI job was accepted as normal.** The extras gate has been failing on `main` for the whole 0.3.1 cycle, which hides the GUI, report and PDF surface again, the same finding as in the previous audit.

## 7. Recommended remediation order

1. **N-P0.2** (HMAC strip): a small, contained change with a large integrity gain.
2. **N-P0.1** plus **N-P1.1**: build the run corpus from registered evidence, align recipe keys, and add an un-mocked end-to-end Case test per recipe.
3. **Fix the CI extras job** (pin `nicegui`, fix mypy) so the GUI, report and PDF tests actually run. Make the PDF test assert `%PDF-` and an embedded figure.
4. **Seal integrity:** N-P1.2, N-P1.3, N-P1.5, N-P1.6, N-P1.7, N-P1.4. Move all sign preconditions into `mark_signed`.
5. **Court wording:** N-P1.8, N-P1.9, N-P1.12. Render everything from `LR_LADDER` and the actual result type.
6. **Method defaults:** N-P1.10 (GI) and N-P1.11 (isotonic bounds).
7. **Silent wrong results:** N-P1.13 (language), N-P1.14 (`method:`), N-P1.15 (seed), N-P1.16 (corpus hash). Then tighten the schema (`extra='forbid'`).
8. The P2 method and metric fixes (PAN metrics, MFW normalisation, CV leakage, consensus), then the docs rewrite, including documenting the Forensic Lab.

## 8. Limits of this audit

- Every agent ran with base `[dev]` extras. WeasyPrint was installed in a scratch location for the PDF checks. NiceGUI was not installed, so GUI findings come from reading the code, not live interaction. `mkdocs build` was not run.
- The literature checks are from the agents' knowledge of the cited papers. Three findings are marked *plausible* (Bezirci-Yılmaz, EderSimpleDelta, the torch CVE applicability) and should be checked against primary sources before acting.
- Zero findings were refuted in adversarial verification. That is consistent with the findings being reproduced empirically, but it also means the verifiers may have been lenient on severity. Severities were re-graded here where the verifiers flagged boundary cases.
- Repro scripts were written to a session scratchpad and are not committed.
