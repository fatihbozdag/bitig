## High-priority findings

### 1. HMAC verification fails open when the signature is removed

**Evidence:** `src/bitig/cases.py:943–952` treats `sig is None` as successful Null-plugin verification, even when `signature_plugin_id` remains `hmac`. A synthetic HMAC-signed case verified successfully after deleting only the `signature` member, even with an incorrect key.

**Impact:** A caller relying on `verify_seal().ok` can accept an artifact whose required cryptographic authentication has disappeared.

**Improve:** Reject missing signatures for non-null plugins; check consistency with the case record; let verifiers require an expected signature scheme/key rather than trusting mutable artifact declarations. Distinguish hash consistency from authentication. Add deletion, null-downgrade, unknown-plugin, and malformed-payload tests.

### 2. Classification preprocessing leaks across validation folds

**Evidence:** `src/bitig/cli/classify_cmd.py:56` and `src/bitig/runner.py:119` fit MFW vocabulary and scaling on the entire corpus before `cross_validate_bitig()` splits the feature matrix (`src/bitig/methods/classify.py:70`).

**Impact:** Held-out documents influence feature selection and standardization. Reported CV scores are not clean estimates for unseen documents; the size and direction of bias have not been measured here.

**Improve:** Cross-validate a complete raw-corpus → fitted extractor → classifier pipeline. Fit every learned transformation inside each training fold. Use grouping appropriate to the claim (source text, event, or duplicate family), and persist fold assignments. The existing sklearn integration test demonstrates pipeline composition but its author-held-out test checks only output shape, despite holding out entire target classes.

This recommendation follows [scikit-learn's pipeline guidance](https://sklearn.org/stable/modules/compose.html), which explicitly places learned preprocessing within CV folds to avoid leakage.

### 3. Accepted study settings do not reliably control execution

**Evidence:** `src/bitig/runner.py:100–129` loads the corpus without `cfg.preprocess.language`; the later pipeline object does not repair the corpus language. A synthetic Turkish study used English function words. At `runner.py:346–354`, classification ignores `cv.folds`, estimator parameters other than the estimator name, and estimator random state. A requested two-fold, seven-tree RF dispatch omitted folds, retained 100 trees, and had `random_state=None` despite study seed 123.

Additional static findings: `group_kfold` is accepted by the schema but unsupported by the CV helper; normalization/cache/report/viz settings are not consumed by the runner; several accepted feature types are skipped with warnings.

**Impact:** Saved configuration can describe an analysis different from the one executed. Repeated randomized runs need not reproduce despite a recorded seed.

**Improve:** Resolve one executable configuration, validate references/IDs/parameters up front, pass language into corpus loading and relevant extractors, propagate folds and estimator parameters, and reject unsupported settings. Store effective settings and realized seeds in results. Add end-to-end configuration contract tests.

### 4. Likelihood-ratio convenience API silently assumes balanced calibration

**Evidence:** `src/bitig/forensic/lr.py:115–157` accepts imbalanced labels but `predict_log_lr()` always uses flat-prior posterior odds. With 100 identical scores and labels split 90/10, the returned LR was approximately **9**, although the score itself contained no class information.

**Impact:** Calibration class prevalence is presented as evidential strength when this API is used on an imbalanced calibration set. This finding concerns the callable calibration API; it does not establish that every shipped case recipe uses it.

**Improve:** Record the effective calibration prior and remove its odds when converting posterior odds to LR, or enforce a balanced/appropriately weighted calibration contract. The module already exposes a prior-aware conversion helper. Test that uninformative scores give LR approximately 1 across class balances; require separate calibration and evaluation data.

### 5. Provenance hashes do not bind important analytical identity

**Evidence:** `src/bitig/corpus/corpus.py:88–92` sorts text hashes separately from document IDs/metadata. Swapping texts between two IDs produced the same corpus hash. `src/bitig/features/base.py:125–134` hashes constructor settings and the transformed corpus but not fitted vocabulary/statistics. Two extractors fitted to different one-word vocabularies produced identical provenance hashes on the same target corpus.

**Impact:** Distinct text-to-label assignments and fitted representations can share an analytical identity. This is a construction flaw, not a cryptographic SHA-256 collision.

**Improve:** Hash canonical `(document_id, text_hash, metadata)` records together. Include training-corpus identity, learned vocabulary/statistics, feature order, and implementation version in fitted-extractor provenance. Preserve reorder invariance only where intended. Add reassignment and different-training-state regression tests.

### 6. Bayesian evaluation and hierarchical model do not match their presentation

**Evidence:** `src/bitig/runner.py:306–326` fits and predicts the same data, recording plain `accuracy`; the Delta branch already labels the equivalent statistic `resubstitution_accuracy`. The local `run_analysis.py` supplies no Bayesian holdout, while the design note describes cross-validated separability. Separately, `src/bitig/methods/bayesian.py:199–205` declares `sigma_group` but fixes `theta_author`'s standard deviation to 1, leaving the group-scale variable disconnected from observations.

**Improve:** Label training accuracy explicitly and implement fold-local evaluation for generalization claims. Correct the design note. Either connect `sigma_group[author_to_group_idx]` to the author prior or remove it and document the intended fixed-scale model. Add model-graph checks and validate posterior diagnostics before interpreting results. No sampling was run in this audit.

### 7. News corpus acquisition is not yet adequate for a four-paper comparison

**Observed local data:** 132 metadata rows and 132 distinct, present files: Hürriyet 59, Sözcü 60, Cumhuriyet 12, Sabah 1. Only three of the five configured events are represented. Sabah and Cumhuriyet occur only for `ceren_ozdemir`, so their newspaper contrasts are also entangled with event coverage. A single Sabah article cannot support ordinary within-class held-out evaluation.

**Collector evidence:** `collect_corpus.py:128` hashes body text, but lines 167–170 save title plus body. All 132 file-byte hashes differ from metadata, and all 132 match after removing the first title block: a checksum-definition mismatch, not evidence of tampering. On resume, only URLs are restored; per-paper caps and overlap calculations apply to newly fetched articles, not the full existing corpus. Filenames omit a URL/content identifier, making same-paper/event/timestamp collisions possible. Archive capture day is stored as `date`, not a verified publication date. `section='body'` accompanies files containing titles.

**Improve:** Preserve separate publication/capture dates and title/body fields; hash final written bytes and name any body-only hash explicitly. Use stable URL-derived IDs and atomic corpus/manifest writes. Recompute duplicate/overlap measures across the complete corpus on resume. Report acquisition coverage by event × paper, manually verify inclusion, and define minimum usable cells before comparison. Restrict initial claims to descriptive patterns in the observed sample; newspaper separability alone does not demonstrate framing or construal.

## Other actionable findings

### 8. Generic CLI reports success after all methods fail

`runner.py:160–167` writes per-method errors and returns normally; `cli/run_cmd.py:26–27` prints “run complete” with exit code 0. Reproduced with a missing feature reference. The case-specific `perform_run` wrapper already handles failure status better, but the generic CLI bypasses it. Reused run names can also leave stale results next to new errors.

Return a structured status from the shared runner; make the CLI fail on total failure and explicitly report partial success. Reject existing run directories or use a deliberate clean replacement policy. Reports should include failed methods instead of silently collecting only available results.

### 9. Function-word z-scoring is a silent no-op

`src/bitig/features/function_words.py:78–87` handles L1/L2 but not its accepted `scale='zscore'`. A synthetic check returned exactly the raw counts. Implement training-fitted statistics or reject this scale. Validate all scale values at the API boundary.

### 10. Cache and dependency handling weaken reproducibility

`src/bitig/preprocess/pipeline.py:113–120` keys cached parses by library versions and model name, but not model-package/weights version. A model update under the same name can reuse old parses. Cache writes are non-atomic (`preprocess/cache.py:61–62`). Record actual model identity and use atomic writes with corruption recovery.

`methods/bayesian.py:26–31` eagerly imports optional PyMC during ordinary package import; this caused the audit's initial ArviZ cache failure before tests could collect. Keep optional imports inside the method that needs them, so a broken optional installation cannot disable basic corpus/CLI operations.

### 11. Sealed HTML does not seal all of its external dependencies

Static inspection: `_canonical_state()` excludes run artifacts, while `signed.html` refers to external run figures (`report/case_report.py:221–240`). Hashing the HTML alone does not bind those image bytes. PDF export reads the external files again. The current figure paths are case-root-relative while browser-opened HTML sits inside `report/`; the PDF exporter supplies a different base URL.

Seal a manifest of result/figure bytes or embed figures in the frozen report; verify it before export. Test image mutation after signing and direct HTML/PDF rendering. This audit did not render a PDF or perform a GUI/browser reproduction.

### 12. MFW rate semantics need an explicit decision

`features/mfw.py:111–131` divides by retained-vocabulary counts rather than total document tokens. With `n=1`, documents containing that word become identical after normalization, even when its full-text frequency differs; a synthetic check confirmed zero z-scores for both documents. This is a different feature definition from the docstring's `count / doc_length` explanation.

Define whether rates are conditional on selected vocabulary or relative to all tokens. Expose/document the choice and validate expected values against an independent reference before claiming named-method parity. Do not silently change defaults without recording the resulting analytical change.

## Recommended implementation order

1. Fail closed on signature removal; bind report assets; repair provenance identity.
2. Make runner configuration executable and explicit; fix fold-local CV, LR prior correction, Bayesian labeling/model wiring, and function-word scaling.
3. Repair collector manifests/resume behavior and audit the event × newspaper sample before any substantive study rerun.
4. Add semantic regression gates: changed settings must change actual execution; training/test separation must hold; tampering must fail; uninformed calibration must remain neutral. Keep Ruff/mypy and existing tests as supporting checks.

The next milestone should be these invariants passing with synthetic fixtures, followed by an explicitly scoped research pilot. More GUI features or additional analytical methods should come later.
